# Homepage Resources Navigation and Footer Verification

Initial direct-anchor testing confirmed the Resources section itself respected the 135px desktop `scroll-margin-top`, placing the section at y=135.28px and its title at y=170.28px. However, the browser did not expose the SPA-managed hash target through the CSS `:target` selector, so the conditional sticky-header rule did not activate and the header remained above the viewport. The implementation was revised to use the homepage’s hash-aware React state and a scoped shell class, preserving normal header behavior for every other destination.

After the scoped hash-state correction, the desktop anchor opens with the shared header sticky at y=0–158.66px and the complete `Free WellBeingFem Resources` title visible at y=170.28px. The section retains its 135px scroll margin, both header and footer Resources links resolve to `/#free-wellbeingfem-resources`, and no horizontal overflow appears. The shared footer computes to exactly `rgb(63, 107, 79)` (`#3F6B4F`), while its existing primary text and navigation links remain readable cream at `rgb(247, 243, 235)`.

The dedicated browser confirms the direct hash-state behavior but does not permit programmatic changes to its inner viewport: `resizeTo(768, 1024)` changes only reported outer dimensions while the rendered inner width remains 1280px. Tablet and mobile validation therefore uses the platform’s explicit 768×1024 and 375×812 responsive captures together with regression assertions for the 119px tablet and 105px mobile offsets.

Independent headless Chromium interaction checks at exact responsive viewports confirm the actual shared header and footer links both open `/#free-wellbeingfem-resources`. At 768×1024, the mobile navigation closes after selection, the header remains sticky at y=0–132.66px, and the full resources title begins at y=153.84px with the 119px offset. At 375×812, the navigation also closes, the header remains at y=0–108.66px, and the full title begins at y=135.13px with the 105px offset. Both viewports have no horizontal overflow. Footer-link interactions reproduce the same header-safe positions and confirm `rgb(63, 107, 79)` on each shared footer. Direct `/resources` navigation no longer renders the former `WellBeingFem Resources` page and instead reaches the Not Found fallback, while the page source file and assets remain untouched.

Full-page desktop captures of Home, ONDAMED, Healy, Guided Meditations, and Research confirm the same shared #3F6B4F footer with existing logo, copy, links, and layout intact on every routed page that includes the site footer. Full-page 768×1024 and 375×812 homepage captures confirm the same green footer, preserved resource carousel, and unchanged responsive page composition. The `/404` fallback remains intentionally separate from the shared site shell and confirms the removed standalone Resources route no longer exposes its former page.

The complete verification run passes all 10 Vitest files and 43 tests, `pnpm run check`, and `pnpm run build`. Existing managed-storage resolution and bundle-size messages remain non-blocking advisories.
