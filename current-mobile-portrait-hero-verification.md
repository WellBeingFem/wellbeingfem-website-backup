## Root-cause repair

The remaining defect was not duplicate mobile anchors. The server-pre-rendered homepage always started with `mobileHeroActive = false`, so mobile visitors initially received the wide desktop hero element while CSS immediately positioned the mobile links using portrait-image percentages. The hero was swapped to the portrait image only after a client `matchMedia` effect ran. This created a timing-dependent interval in which the active touch rectangles were calculated against the wrong hero box, explaining the intermittent and non-independent behavior on real mobile loads.

The JavaScript-delayed image branch and media-query state were removed. The existing hero now uses one stable responsive `<picture>` whose mobile and desktop `<source media>` elements let the browser select the correct image before hydration. No new overlay set was added; the same two existing mobile HTML anchors remain. A no-JavaScript production-build check at 375px confirmed that the portrait box and both anchors have correct geometry before hydration, preserve a 31.52px non-clickable flower gap, and natively navigate to the visible ONDAMED card and the top of `/resources`. Hydrated real-touch tests passed at 320px, 375px, and 390px; mobile and desktop screenshots confirmed no visual change. The full 65-test suite, TypeScript validation, and production build passed.

After the stable responsive-picture bundle fully propagated, live real-touch tests passed at 320px, 375px, 390px, and 430px. At every width, each link was the topmost hit-tested element at its centre. Explore Sessions opened `/#ondamed-service-card` with the card approximately 24px below the viewport top; Start with a Free Resource opened `/resources` at scroll position zero. The non-clickable flower gap scaled from 26.89px to 36.16px across these widths. The live HTML contains two native mobile `<source media="(max-width: 767px)">` elements and no JavaScript-delayed mobile hero state.
